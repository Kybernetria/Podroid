## Repeat the Gradle-only measurement

First verify the commit and record whether ignored native/VM inputs are absent:

```bash
distrobox enter android-dev -- bash -lc '
  set -euo pipefail
  cd "$(git rev-parse --show-toplevel)"
  git rev-parse HEAD
  git status --short
  for path in \
    app/src/main/assets/vmlinuz-virt \
    app/src/main/assets/initrd.img \
    app/src/main/assets/alpine-rootfs.squashfs \
    app/src/main/jniLibs/arm64-v8a/libqemu-system-aarch64.so \
    app/src/main/jniLibs/arm64-v8a/libslirp.so \
    app/src/main/jniLibs/arm64-v8a/libpodroid-bridge.so \
    app/src/main/jniLibs/arm64-v8a/libpodroid-launcher.so
  do
    if test -e "$path"; then stat -c "PRESENT %n %s bytes" "$path"; else echo "MISSING $path"; fi
  done
'
```

Run tests/build and emit machine-readable measurements:

```bash
distrobox enter android-dev -- bash -lc '
  set -euo pipefail
  cd "$(git rev-parse --show-toplevel)"
  ./gradlew :app:testDebugUnitTest assembleDebug
  apk=app/build/outputs/apk/debug/app-debug.apk
  printf "commit=%s\n" "$(git rev-parse HEAD)"
  printf "apk_bytes=%s\n" "$(stat -c %s "$apk")"
  printf "apk_sha256=%s\n" "$(sha256sum "$apk" | awk '\''{print $1}'\'')"
  printf "native_lib_count=%s\n" "$(unzip -Z1 "$apk" | grep -Ec '\''^lib/[^/]+/[^/]+[.]so$'\'')"
  printf "source_manifest_permission_count=%s\n" "$(grep -c '\''<uses-permission '\'' app/src/main/AndroidManifest.xml)"
  unzip -Z1 "$apk" | grep -E '\''^lib/[^/]+/[^/]+[.]so$'\'' | sort
'
```

Record the exact output. If size or native count differs, compare the generated-input inventory before calling it a regression.

## Device measurement protocol

Do not mix QEMU and AVF samples. Record backend, VM RAM/vCPU/storage settings, Downloads sharing, USB, SSH, port forwards, X11 state, Android thermal state, battery/charger state, and whether guest storage is fresh. Take at least five boots per backend/state and report every sample plus median; do not report only the best run.

### Device metadata

```bash
distrobox enter android-dev -- bash -lc '
  set -euo pipefail
  adb get-state
  adb shell getprop ro.product.manufacturer
  adb shell getprop ro.product.model
  adb shell getprop ro.build.fingerprint
  adb shell getprop ro.build.version.release
  adb shell getprop ro.build.version.sdk
  adb shell getprop ro.boot.hardware
  adb shell cat /proc/meminfo | sed -n "1,6p"
'
```

### Install the measured APK

```bash
distrobox enter android-dev -- bash -lc '
  set -euo pipefail
  cd "$(git rev-parse --show-toplevel)"
  apk=app/build/outputs/apk/debug/app-debug.apk
  test -f "$apk"
  sha256sum "$apk"
  adb install -r "$apk"
'
```

For AVF, separately record whether both development permissions were granted; do not infer AVF use from device model alone:

```bash
distrobox enter android-dev -- bash -lc '
  set -euo pipefail
  pkg=com.excp.podroid.debug
  adb shell dumpsys package "$pkg" | grep -E "MANAGE_VIRTUAL_MACHINE|USE_CUSTOM_VIRTUAL_MACHINE"
'
```

### RAM samples

Capture an idle-app sample before VM start, then the same commands after the Home screen reports Running and again after five minutes. `dumpsys meminfo` is the primary per-process source; `/proc/meminfo` gives device-wide context.

```bash
distrobox enter android-dev -- bash -lc '
  set -euo pipefail
  pkg=com.excp.podroid.debug
  stamp=$(date -u +%Y%m%dT%H%M%SZ)
  mkdir -p baseline-results
  adb shell dumpsys meminfo "$pkg" > "baseline-results/${stamp}-app-meminfo.txt"
  adb shell cat /proc/meminfo > "baseline-results/${stamp}-device-meminfo.txt"
  adb shell dumpsys thermalservice > "baseline-results/${stamp}-thermal.txt"
  printf "saved prefix baseline-results/%s\n" "$stamp"
'
```

Label each output as `idle`, `qemu-running-0m`, `qemu-running-5m`, `avf-running-0m`, or `avf-running-5m`. Report Total PSS and Total RSS from `dumpsys meminfo`, plus device `MemAvailable`; do not substitute configured guest RAM for observed process RAM.

### Boot samples

The app measures boot duration from engine start to the backend-neutral `Ready!` transition and displays the last value on Home. Record that displayed duration for each run. Also preserve `console.log` as evidence that readiness came from the guest marker rather than the safety timeout:

```bash
distrobox enter android-dev -- bash -lc '
  set -euo pipefail
  pkg=com.excp.podroid.debug
  stamp=$(date -u +%Y%m%dT%H%M%SZ)
  mkdir -p baseline-results
  adb shell run-as "$pkg" cat files/console.log > "baseline-results/${stamp}-console.log"
  grep -n "Ready!" "baseline-results/${stamp}-console.log"
'
```

A cold sample means a documented fresh `storage.img`/first guest boot and includes first-boot work. Deleting `storage.img` destroys guest data, so do it only on a disposable test install and state that explicitly. A warm sample reuses the same guest disk after a clean VM stop. QEMU and AVF have different console transports but must use the same `Ready!` endpoint.
