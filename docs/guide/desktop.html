Desktops & the X11 viewer

The inherited Android VNC viewer remains visible during staged refactoring, but the minimal guest has no bundled endpoint. It does not ship Xvnc, PulseAudio, a desktop, X11/font packages, DISPLAY defaults, port 5900/4713 listeners, or automatic display/audio forwards.

Optional manual provisioning

You may install a desktop, fonts, an RFB server, and audio software from Alpine repositories later. That software and its security configuration are guest-owned: review the packages, authentication, bind addresses, and explicit port-forward rules before exposing an endpoint. Podroid does not configure or start one for you.

No endpoint is bundled or tested

The retained viewer speaks RFB, not Wayland. Installing desktop packages alone does not create a compatible or secure RFB endpoint, and the current minimal release does not promise a one-command desktop setup.

Example session commands

The commands below are desktop session examples only. They work only after you install and configure the selected desktop and your own X11/RFB server, set DISPLAY, and add any required explicit forward.

# Xfce example
$ startxfce4 &

# LXQt example
$ startlxqt &

# MATE example
$ mate-session &
Avoid implicit network exposure

Do not enable a display manager or RFB service until you have reviewed its authentication and listener configuration. The base image deliberately creates no listener.

Single GUI apps

Individual X11 applications likewise need a separately installed and configured X server; DISPLAY is not preset by the minimal guest:

# apk add firefox
$ firefox &

This does not display anything until your guest-owned X11/RFB endpoint is running and reachable through an explicit rule.

Viewer settings reference

The retained Android viewer still exposes its legacy client settings. They have no effect until a compatible guest endpoint is provisioned manually.

Resolution

Requests an RFB framebuffer size from a manually provisioned server that supports the ExtendedDesktopSize extension.

  • Match viewport - the desktop tracks your screen size exactly, resizing whenever the viewer resizes. Pixel-perfect on most devices.
  • Preset - fixed resolutions: 720p, 900p, 1080p, or 1440p. Pick a lower preset for smoother rendering on heavy desktops over a high-DPI display.
  • Custom - enter any width and height in pixels.

Touch input

  • Direct - tap to click at the point you touch; drag to drag; long-press activates drag-lock. Intuitive for touch-first use.
  • Trackpad - relative pointer: your finger position moves the cursor rather than placing it. Sensitivity is adjustable (0.5x to 3.0x) with optional pointer acceleration.

In both modes: two-finger tap sends a right-click; two-finger drag scrolls.

External input

A connected hardware keyboard passes through fully, including Ctrl, Alt, Shift, and composed shortcuts (e.g. Ctrl+L in a browser). An external mouse's scroll wheel scrolls, and all three buttons map to their X11 equivalents.

Other settings

Setting Notes
Fullscreen Hides the system UI. Back exits fullscreen.
Rotation lock Auto, Landscape, or Portrait. Auto follows the device sensor.
Extra-keys bar Show or hide the keyboard shortcut bar below the viewer.
Server DPI Legacy client preference for a compatible manually provisioned server; the minimal guest has no Xvnc process to consume it.
Audio Legacy client toggle only. PulseAudio and the port 4713 listener/forward are not bundled.
Known limitation: external mouse right-click

With an external mouse, right-click currently exits fullscreen instead of reaching the desktop. Android maps the mouse's right button to the Back action. Two-finger touch right-click works correctly as a workaround. A fix is planned.

Performance

The viewer currently uses uncompressed Raw encoding (ZRLE was disabled after it desynced on complex content). On a high-DPI phone, selecting the 720p or 900p preset reduces the amount of screen data transferred each frame and noticeably improves smoothness on heavy desktops. See the Performance page for general tuning advice.
